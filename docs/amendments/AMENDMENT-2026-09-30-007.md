## Motivo
O Doc 02 define POST /publications/{id}/retry e manual-fallback, mas não há como confirmar que uma publicação manual (EXPORT) foi de fato postada — o status PENDING nunca viraria PUBLISHED pela API especificada.

## Documento afetado
Documento 02 (Publication), Documento 14

## Regra anterior
Lacuna: transição PENDING→PUBLISHED sem endpoint.

## Nova regra
Adicionar POST /api/v1/publications/{id}/confirm (marca PUBLISHED com published_at + remote_id opcional), restrito a publicações EXPORT/MANUAL em PENDING, auditado. Publicações via API de plataforma confirmam pelo retorno do adapter (Doc 14).

## Impacto de produto
Fecha o ciclo do método EXPORT (postagem manual confirmada).

## Impacto arquitetural
Nenhum — publicações já têm status/published_at.

## Impacto de segurança
Auditoria obrigatória no confirm (quem confirmou).

## Impacto de dados
Nenhum.

## Impacto de compatibilidade
Endpoint novo, aditivo.

## Testes necessários
Testes: confirm só de PENDING; PUBLISHED ganha published_at; audit escrito.
